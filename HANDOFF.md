# Afterhour — HANDOFF

Jira project **H4N** (Epic H4N-1) is the source of truth for tasks. This page keeps what Jira scatters across comments: **the core ideas, the decisions and why, and the UI rules.** Update it whenever a decision changes.

## Core ideas

- **What it is:** a desktop web typography tool. The user brings a font and text; rain on glass deforms the letters. The final output is an **installable rain font** (OTF/WOFF2, variable **RAIN** axis 0–100), not a video.
- **Persona:** 闹市夜雨, night rain in a busy city.
- **Result-oriented, but extreme:** the aim is to express an idea. Engineering stays proportionate, but **professionalism and beauty are pushed to the extreme together**. "Fine" is not the bar.
- **Be ambitious** ([robonuggets/be-ambitious](https://github.com/robonuggets/be-ambitious)): find the goal beyond the goal (Altitude). Work like the field's best from raw material, e.g. glyph outlines and reference photos, not guesses (Depth). Borrow other fields' methods (Range). **Never grade our own work:** use an outside judge such as OTS/fontTools, side-by-side comparison with reference photos, or Yunhan.
- **Decide with options:** before any decision, especially UI, show Yunhan **3–5 options with mockups** and a recommendation. Mockups use **Garamond (EB Garamond) or Arial (Arimo)**.
- **Record decisions:** create tickets / comment in Jira for every decision, and update this file.

## Working rules

- Work inside the ticket's scope; ask in a ticket comment. No publishing, domains or spending without Yunhan.
- Branches `feature|bug|chore/H4N-<n>-<slug>`, one PR per ticket into `main`; Yunhan reviews and merges (merge commits, not squash, because PRs are often stacked).
- Static site on GitHub Pages (public repo `OpsDLC/Afterhour`), deployed by Actions on every push to `main`.
- Reusable parts go to **OpsDLC/DLC-UI** later (label `dlc-ui-candidate`); keep them free of app-specific imports.

## UI rules

- **Desktop only.** Below 1024px show a notice with "Open anyway". (No mobile: not worth the work for a tool this complex.)
- **Colours:** white background, black text. **International Klein Blue `#002FA7` only for interaction** (focus, selected, sliders, active tab). Everything else derives from `--bg`, `--text`, `--accent`.
- **UI font:** the system UI font. The preview shows the user's font.
- **Trade vocabulary**, no simplifying. The audience is typographers: tracking, leading, measure, Squint view.
- **Hide what's rare, group what belongs together.** Use tabs and drawers deliberately. The preview is the hero.
- **Beauty pass on every new UI (Yunhan, 2026-10-31).** Any time new UI goes into the panel or onto the screen, design it for beauty before showing it: a clear type hierarchy, an aligned grid, generous and consistent spacing, hairlines rather than boxes, a single accent. A functional wireframe is not a mockup. Look at it critically, as an outside judge would, before sending it.
- Layout: collapsible sidebar, Text pinned on top, tabs **Type / Layout / Rain**; preview fills the rest.
